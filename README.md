# My AI Novel

My AI Novel 是一个本地运行的结构化小说生产流水线桌面程序。它面向长篇、连载和轻小说式创作，目标不是只让模型“写一段文本”，而是把项目设定、资料库、章节规划、小节任务、正文生成、审稿改写和定稿导出串成一个可以反复使用的写作工作流。

当前版本的重点是：通过标签化方式生成小说初始内容，自动创建角色卡，基于资料库和章节状态做更连续的自动化写作。

## 当前特色

- 标签化生成小说初始项目：像选择小说站标签一样选择故事标签、写作标签和排除标签，生成候选小说方案。
- 自动化角色卡：保存项目后可引导创建主要角色，也可以调用 API 根据项目信息自动生成默认主要角色卡。
- 资料库优先写作：角色卡、地点、组织/势力、规则、时间线、伏笔和禁止事项会进入项目资料库，后续章节写作可调用这些资料。
- 更完整的自动化写作：支持从当前小节开始自动生成正文、审稿、按意见改写、定稿后继续下一节，并可设置自动切换到下一章。
- Scrivener / Obsidian 风格项目存储：一个小说项目就是 `projects/` 下的一个文件夹，真实数据尽量保存为 `.json`、`.md`、`.txt` 等人能直接打开的文件。
- OpenAI-compatible API：支持填写 `base_url`、`api_key`、模型名称、请求路径模式和写作参数。
- 本地桌面 UI：当前主界面为 PySide6，保留 legacy tkinter / CustomTkinter 回退代码。

## 已实现功能

### 项目与大纲

- 创建、保存、切换小说项目。
- 管理题材、写作风格、目标读者、叙事视角、世界观、风格说明和总体概括。
- 支持手动创建项目，也支持“标签化生成”项目候选。
- 总框架页支持整书模式和连载模式。
- 整书模式用于生成整本书的大纲。
- 连载模式用于生成当前一部分剧情，也支持继续生成下一部分大纲。
- 用户确认后才会把大纲拆分为章节。
- 连载模式新增大纲时，确认拆分会把新章节追加到原有章节后面。
- 章节列表包含标题、时间、地点、人物、目标、冲突、节奏、钩子等可编辑信息。
- 支持章节和小节的新增、删除、上下移动。

### 资料库

- 资料库类型包括：角色卡、地点、组织/势力、规则、时间线、伏笔、禁止事项和其他资料。
- 角色卡基础信息包括身份、性格、动机、说话风格、人物弧光、与其他角色的关系等。
- 角色卡支持查看和编辑完整 JSON，便于保存不固定的标签化信息，例如等级、技能、TS、恋爱关系、群像定位等。
- 资料库侧边栏按当前类型显示条目，避免一次性显示全部资料。
- 支持手动创建、编辑、删除资料。
- 支持 AI 自动创建当前类型资料。
- 支持 AI 自动补充资料设定，并可输入补充方向。
- 总框架生成会参考资料库已有内容；章节写作可调用资料库中的相关角色、地点、事件、伏笔和禁止事项。
- 每章完成后可总结与被调用资料相关的剧情影响，并反写到资料详情中。

### 检索与记忆

- 写作前可按当前章节/小节检索相关资料。
- 区分长期设定、近期剧情和当前场景目标。
- 支持关键词检索、标签检索和可选向量检索。
- 没有 embedding 模型时会自动降级到关键词和标签检索。
- 资料库优先级倾向于组织/势力与角色卡，其次是伏笔、地点和时间线。

### 多 Agent 写作流水线

内置固定写作流水线：

```text
全书架构 Agent
-> 章节架构 Agent
-> 小节规划 Agent
-> 场景导演 Agent
-> 对白/心理 Agent
-> 正文写作 Agent
-> 审稿 Agent
-> 改写 Agent
```

当前 UI 中最常用的流程是：

1. 生成或完善全书故事大纲。
2. 用户确认后拆分章节。
3. 在章节页确认章节和小节信息。
4. 调用资料库。
5. 生成正文粗稿。
6. 审稿。
7. 按审稿意见改写。
8. 锁定定稿。
9. 继续下一节或下一章。

### 正文、审稿与改写

- 正文生成默认模式为“粗稿”。
- 支持粗稿、精写、扩写、压缩、润色等写作模式。
- 正文生成时会参考项目世界观、风格说明、叙事视角、章节/小节任务和检索到的资料。
- 审稿检查人物 OOC、世界观矛盾、时间线错乱、伏笔遗漏、提前泄露、重复表达、节奏拖沓和聊天化废话等问题。
- 改写 Agent 根据审稿问题列表修改正文。
- 支持局部改写方向，例如只改对白、只改心理、只改结尾、增强冲突等。
- 支持定稿和取消定稿。
- “继续下一节”要求上一节已定稿。

### 自动化写作

- 写作页支持自动化勾选。
- 章节页支持从当前选中小节开始自动化写作。
- 自动化可按顺序执行正文生成、审稿、改写、定稿、继续下一节。
- 支持用户通过按钮中断自动化。
- 支持 API 访问失败时按策略重试，直到成功或用户中断。
- 自动化写作采用后台线程，避免长时间模型请求卡住整个 UI。
- 写作界面底部有当前流式生成内容区域，用于显示正在生成的文本。

### LLM 配置

- 兼容 OpenAI API 协议的模型提供商。
- 可配置 Base URL、API Key、代理地址、请求路径模式、正文模型、架构/审稿模型、Embedding 模型。
- 支持 `/chat/completions` 和 `/responses` 请求模式。
- 支持扫描 Provider 的 `GET /models` 结果。
- 支持手动模型候选；远程扫描失败时仍可使用手动填写的模型。
- 可配置最大 token、Temperature、Top-P、Top-K、Presence Penalty、Frequency Penalty。
- API key 保存到当前目录下的 `.json/llm_config.json`，不会写入项目文件夹。
- 支持 HTTP/HTTPS 代理地址，例如 `http://127.0.0.1:7890`。

### 版本与导出

- 每次生成正文会保存版本。
- 支持定稿、取消定稿和保留候选版本。
- 支持比较和回滚旧版本。
- 支持导出全书 Word。
- 导出全书时只导出已定稿小节，未定稿小节会跳过。
- Word 导出使用 Python 标准库生成基础 `.docx`，不需要额外安装 `python-docx`。

## 安装要求

### 必须安装

- Python 3.11 或更高版本。
- pip。
- 项目依赖：

```powershell
python -m pip install -r requirements.txt
```

当前 `requirements.txt` 包含：

```text
PySide6
CustomTkinter
```

### 需要自己准备

- 一个兼容 OpenAI API 协议的 LLM 服务。
- 该服务的 Base URL。
- API Key。
- 至少一个可用模型名称。
- 如果你的模型服务需要代理，还需要本地 HTTP/HTTPS 代理地址。

### 可选工具

- Microsoft Word、WPS 或 LibreOffice：用于打开导出的 `.docx` 文件。
- Git：如果你想从 GitHub 克隆源码并跟踪更新。

不需要额外安装数据库。程序会在本地自动创建运行所需的 `projects/`、`data/` 和 `.json/` 目录。

## 快速开始

```powershell
git clone https://github.com/sEwhappend/MyAINovel.git
cd MyAINovel
python -m pip install -r requirements.txt
python run.py
```

如果你下载的是 GitHub Release 压缩包，解压后在解压目录运行：

```powershell
python -m pip install -r requirements.txt
python run.py
```

## 基础使用流程

1. 启动程序：`python run.py`。
2. 在“项目”页新建项目。
3. 选择手动填写，或使用“标签化生成”创建小说初始方案。
4. 保存项目后，按引导去资料库创建主要角色，或调用 API 自动生成主要角色卡。
5. 在“设置”页填写 Base URL、API Key、模型和写作参数。
6. 点击“测试连接”和“扫描模型”确认 API 可用。
7. 在“总框架”页生成全书故事大纲。
8. 修改满意后，手动点击确认并拆分章节。
9. 在“章节”页检查章节与小节，补充时间、地点、人物、目标和冲突。
10. 在“写作”页调用资料库，生成正文粗稿。
11. 审稿并按意见改写。
12. 锁定定稿。
13. 继续下一节，或使用自动化写作。
14. 在“项目”页导出全书 Word。

## 数据存储

默认项目目录：

```text
projects/
  project-<id>-<项目名>/
    project.json
    worldbook.md
    style.md
    library/
    chapters/
    versions/
    exports/
```

本地运行目录：

```text
.json/
  llm_config.json      # 本地 API 配置，不建议上传

data/
  novel.db             # SQLite 索引、日志和兼容旧数据

projects/
  ...                  # 用户小说项目
```

设计目标是让小说项目尽量像 Scrivener / Obsidian 一样，一个项目就是一个文件夹。SQLite 可以保留为缓存、索引、日志或旧数据迁移来源，但不应该是用户唯一能访问的真实数据。

## 设置说明

在“设置”页填写：

- Base URL：例如 `https://api.example.com/v1`。
- API Key：模型服务提供的密钥。
- 代理地址：可选，例如 `http://127.0.0.1:7890`。
- 请求模式：`/chat/completions` 或 `/responses`。
- 正文模型：用于正文生成。
- 架构/审稿模型：用于大纲、审稿等更需要推理的步骤。
- Embedding 模型：可选，用于向量检索。
- 模型候选：可选，每行一个模型 ID。
- 超时秒数。
- 最大 token。
- Temperature。
- Top-P。
- Top-K。
- Presence Penalty。
- Frequency Penalty。

点击“扫描模型”会请求：

```text
GET {base_url}/models
```

扫描成功后会显示 Provider 返回的模型列表。扫描失败不会清空你已经填写的模型。

## 已知限制

- 当前 UI 仍在从旧 tkinter / CustomTkinter 逐步迁移到 PySide6。
- 标签化生成项目已经可用，但还没有真正做到完整的“像搜索小说一样生成小说”。
- 人物标签化生成还没有完全成型，目前角色卡支持保存完整 JSON，但角色创建流程仍在迭代。
- 自动化写作依赖模型服务稳定性；Provider 返回 503、524、499 等错误时，需要结合 Provider 日志和本地网络判断。
- Word 导出是基础 `.docx`，暂不包含复杂排版样式。
- 审稿质量依赖资料库质量和模型能力。
- 混合 DPI、多屏、不同 Windows 缩放比例下的无边框窗口体验仍需要继续打磨。

## 后续计划

- 真正实现“像搜索一样生成小说”：用户像在小说网站搜索一样输入需求、选择标签、排除标签、查看候选小说方案，再生成项目。
- 扩充标签库，区分故事标签、写作标签、结构标签、角色标签和需要长期状态跟踪的标签。
- 实现人物的标签化生成：先选择主角定位、POV、群像关系、重要配角类型、特殊身份或关系标签，再自动生成角色卡。
- 把标签与资料库模块打通：例如等级体系、技能、阵营、恋爱关系、论坛体等标签能够写入角色卡或对应资料 JSON，而不是只写进提示词。
- 优化自动化写作的上下文组织，让项目级世界观、风格和固定规则稳定复用，章节、小节和检索资料按需追加。
- 继续美化 PySide6 UI，完善项目书架、资料库编辑、章节排布和写作面板。
- 增强导出能力，支持更完整的 Word 样式和可能的 Markdown 导出。
